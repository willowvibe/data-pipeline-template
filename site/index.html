What it is

The sample pipeline fetches hourly weather for Bengaluru, London and New York from Open-Meteo. It keeps the raw JSON, loads it idempotently into a warehouse, and models it with dbt. Replace the source and models; keep the tested plumbing.

Raw data kept for replay

One validated JSON file per city per UTC date. Fix a model or loader and rerun without calling the API.

Idempotent loads

Delete-then-insert per city and date inside one transaction. Re-runs replace data instead of duplicating it.

Offline by default

A recorded fixture is re-dated to today, so pytest, make ci and demos never depend on the network.

Real quality gates

ruff, sqlfluff, pre-commit, pytest, dbt tests and source freshness are wired into the generated CI.

Choose your stack

The warehouse and orchestrator are independent options, so all four combinations work.

Warehouse

DuckDB or Postgres

DuckDB is a single local file with no services. Postgres 16 runs in Docker Compose with a health check and environment-based credentials.

Orchestrator

Make or Airflow

Plain Makefile targets for a small project, or Airflow 3.4 with a Cosmos DAG where every dbt model and test is its own task.

Everything else

Generated, not assumed

Cities, package name, ports, warehouse profile, dbt seed and CI workflow all come from the Copier answers.

What CI proves

Four combinations, every push

The template CI renders duckdb/postgres × none/airflow, installs each project in a fresh Python 3.12 virtualenv, and runs its generated make ci: lint, offline tests, an offline extract and load, dbt seed, dbt build and source freshness.

Postgres legs use a postgres:16 service. Airflow legs also run airflow db migrate and airflow dags test in a temporary AIRFLOW_HOME.

  • DuckDB + Make
  • DuckDB + Airflow
  • Postgres + Make
  • Postgres + Airflow
  • Weekly live Open-Meteo job, separate from pull requests
  • copier update tested from the newest tag
